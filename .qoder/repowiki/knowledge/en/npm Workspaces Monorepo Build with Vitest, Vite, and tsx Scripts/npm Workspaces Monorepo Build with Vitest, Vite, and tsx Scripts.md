## Build System Overview

This is a **Node.js npm workspaces monorepo** (`trip-graph-agent`) that builds two applications — a Fastify API (`apps/api`) and a React/Vite web app (`apps/web`) — plus a shared TypeScript package (`packages/shared`). There are no Makefiles, Dockerfiles, or CI pipelines in the repository; build orchestration lives entirely in `package.json` scripts and Node.js helper scripts under `scripts/`.

### Workspace Layout

- Root `package.json` declares `workspaces: ["apps/*", "packages/*"]`, enabling cross-package dependency resolution via `@yuanfen/shared` (referenced as `*`).
- Each workspace has its own `package.json`, `tsconfig.json`, and test directory. The root `vitest.config.ts` configures Vitest to discover tests in both `packages/*/test/**/*.test.ts` and `apps/api/test/**/*.test.ts`.
- All packages use `"type": "module"` (ESM) and share a root `tsconfig.base.json` for common TypeScript settings.

### Dev & Test Commands

| Command | What it does |
|---|---|
| `npm run dev` | Runs both apps concurrently via `concurrently`: `tsx watch src/server.ts` for the API and `vite` for the web dev server |
| `npm run test` | Runs `vitest run` across all workspace packages |
| `npm run fareboard` | Executes the nightly job script `tsx apps/api/src/jobs/run_fareboard.ts` |

The API uses **tsx** (TypeScript execution) rather than a compiled artifact — there is no `build` step for `@yuanfen/api`. The web app uses **Vite** with standard `dev` / `build` / `preview` scripts. The shared package is consumed directly from source via the `exports` field pointing at `./src/index.ts`, so it is never built separately.

### Data Pipeline Scripts

Two Node ESM scripts under `scripts/` drive data generation and validation:

- `scripts/build-matrix.mjs` — Generates pairwise travel-time matrices (`data/routing/<city>.json`) from place coordinates in `data/places/*.json`. It attempts OSRM's public routing API first; on failure it falls back to a haversine-based driving estimate (24 km/h × 1.35 route factor + 7 min overhead). Walking legs ≤ 2.0 km are estimated at 4.5 km/h + 2 min buffer. Output files are checked into version control.
- `scripts/verify-breadth.mjs` — Validates every city fixture: checks for duplicate IDs, valid lat/lng, complete `openHours` (either 7 weekday keys or `{daily}` shorthand), unknown `vibeTags` against the canonical list in `packages/shared/src/types.ts`, and matrix shape consistency between `data/places` and `data/routing`. Exits non-zero if any city fails.

### Conventions

- **No compilation artifacts**: Everything runs from source via `tsx` and Vite's dev server. Only the web app produces a static build via `vite build`.
- **Shared types as source**: `@yuanfen/shared` exports raw `.ts` files through its `exports` map; consumers import from `@yuanfen/shared` and rely on their own TS compiler to resolve them.
- **Data-driven fixtures**: Place metadata, routing matrices, fares, and holidays live in `data/` as JSON and are regenerated by Node scripts rather than generated at build time.
- **Tests are co-located**: Each package keeps its tests in a sibling `test/` directory, discovered automatically by the root Vitest config.
- **No containerization or CI**: There are no Dockerfiles, GitHub Actions, or release scripts in this branch. Deployment and packaging are not part of the repository.
