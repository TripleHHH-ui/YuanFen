## System / Approach

The repository is a **single npm workspace monorepo** managed entirely through `npm` (no Yarn/PNPM/Bun). The root `package.json` declares the workspaces via the `workspaces: ["apps/*", "packages/*"]` field, which automatically hoists shared dev dependencies and links local packages together. All third-party dependencies are resolved from the public npm registry — there is no private registry, `.npmrc`, or vendored `node_modules` committed to version control.

A single `package-lock.json` at the repo root acts as the **canonical lockfile** for the entire workspace, pinning every transitive dependency to an exact version and integrity hash. This ensures deterministic installs across all subprojects (`@yuanfen/api`, `@yuanfen/web`, `@yuanfen/shared`).

## Key Files

- `package.json` (root) — workspace declaration, top-level scripts (`dev`, `test`, `fareboard`), and shared devDependencies (`typescript`, `vitest`, `tsx`, `concurrently`, `@types/node`).
- `package-lock.json` — full lockfile for the workspace; generated by npm v7+ (lockfileVersion 3).
- `apps/api/package.json` — Fastify API server; depends on `fastify`, `@fastify/cors`, and the internal `@yuanfen/shared` package via the workspace wildcard `*`.
- `apps/web/package.json` — Vite + React frontend; depends on `react`, `react-dom`, `zustand`, `maplibre-gl`, and `@yuanfen/shared`.
- `packages/shared/package.json` — internal shared library (`@yuanfen/shared`); marked `private: true` so it is never published, exposes its entry via `exports: { ".": "./src/index.ts" }`.
- `tsconfig.base.json` — shared TypeScript compiler options (`target: ES2022`, `module: ESNext`, `moduleResolution: bundler`, `strict: true`) consumed by each workspace's own tsconfig.

## Architecture & Conventions

1. **Workspace-local linking over versioning**: Internal packages reference each other with the `*` range (e.g., `"@yuanfen/shared": "*"` in both `apps/api` and `apps/web`). Because they live in the same workspace, npm resolves them to the local filesystem path rather than publishing/verifying against the npm registry. This means the shared package has no semver contract enforced by the manifest — consumers must stay compatible manually.

2. **Single source of truth for versions**: All third-party dependency versions are declared only in the leaf `package.json` files under `apps/*` and `packages/*`. The root `package.json` only holds cross-cutting dev tooling. There is no central `dependencies.yaml` or policy file.

3. **No vendoring**: `node_modules/` exists locally but is not tracked in git (standard npm behavior). Dependencies are always fetched fresh from the public npm registry during install.

4. **TypeScript module resolution**: Each workspace uses `moduleResolution: "bundler"` (inherited from `tsconfig.base.json`), which allows the `exports` field in `packages/shared/package.json` to be respected by the TS compiler and bundlers. This is what lets `apps/api` and `apps/web` import `@yuanfen/shared` directly from its `src/index.ts` without a separate build step.

5. **Dev-time tooling is centralized**: `tsx` is used to run TypeScript directly in both the API (`tsx watch src/server.ts`) and the root `fareboard` script (`tsx apps/api/src/jobs/run_fareboard.ts`), avoiding a pre-build step for Node-side code.

## Rules Developers Should Follow

- **Add new third-party dependencies only inside the relevant workspace's `package.json`** (`apps/api`, `apps/web`, or `packages/shared`). Do not add them to the root `package.json` unless they are truly shared dev tooling.
- **Use caret ranges (`^x.y.z`) for external libraries** (as seen throughout the repo) to allow minor/patch updates while keeping major-version boundaries explicit.
- **Never publish `@yuanfen/shared`**: It is marked `private: true`; treat it as an internal implementation detail shared between `apps/api` and `apps/web`.
- **Always commit `package-lock.json` changes**: Since this is the single lockfile for the whole workspace, any dependency change must be reflected there to keep CI and teammates' installs deterministic.
- **Reference internal packages by their workspace name** (`@yuanfen/shared`) using the `*` range — do not hardcode paths or publish versions.
- **Keep TypeScript config consistent**: New workspaces should extend `tsconfig.base.json` to inherit the shared compiler options rather than redefining them.
- **Do not introduce another package manager**: The repo relies exclusively on npm workspaces; adding Yarn/PNPM would break the single lockfile model.
